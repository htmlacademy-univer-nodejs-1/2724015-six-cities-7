# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Подготовить конфигурацию

Создайте локальный `.env` по примеру `.env-example`:

```bash
cp .env-example .env
```

Заполните обязательные переменные: `PORT` — номер порта, `DB_HOST` — IP-адрес сервера базы данных, `SALT` — непустая строка со случайными символами. Замените пример соли своим значением. `.env` исключён из Git.

При запуске dotenv читает `.env`, затем convict проверяет значения. Переменные, уже установленные в окружении, имеют приоритет над `.env`. При ошибке приложение выводит сообщение через логер и завершает работу. В лог попадают сообщение об инициализации и номер порта.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

#### Запустить с удобным выводом логов

```bash
npm run start:dev
```

Собирает приложение и передаёт JSON-логи pino в pino-pretty. Обычный `npm start` выводит логи в JSON. Пока приложение только проверяет конфигурацию и сообщает об инициализации, HTTP-сервер ещё не запускается.

## Структура проекта

### Директория `src`

Исходный код проекта разделён по назначению:

- `src/cli` — команды CLI и их интерфейсы.
- `src/rest` — приложение REST API. Новые модули API размещаем в `src/rest/modules`, каждый в своей директории.
- `src/shared/libs` — общие компоненты: логер и конфигурация. Каждый компонент находится в отдельной директории вместе со своим интерфейсом и типами.
- `src/shared/container` — DI-контейнер и идентификаторы зависимостей.
- `src/shared/helpers`, `src/shared/types`, `src/shared/generators` — вспомогательные функции, общие типы и генераторы данных.
- `src/main.ts` и `src/main.cli.ts` — точки входа REST-приложения и CLI.

Файлы называем строчными буквами через дефис, классы — в PascalCase. Интерфейсы храним в файлах `*.interface.ts`, типы — в `*.type.ts`. Зависимости REST-компонентов передаём через конструктор с помощью Inversify. Регистрацию зависимостей добавляем в контейнер.

### Файл `Readme.md`

Инструкции по работе с учебным репозиторием.

### Файл `Contributing.md`

Советы и инструкции по внесению изменений в учебный репозиторий.

### Остальное

Все остальные файлы в проекте являются служебными. Пожалуйста, не удаляйте и не изменяйте их самовольно. Только если того требует задание или наставник.

#### Запустить тестовый REST API

```bash
npm run mock-server
```

Запускает JSON-server на порту 3000 с данными из `mocks/mock-server-data.json`.

#### Сгенерировать тестовые предложения

Сначала запустите тестовый REST API, затем в другом терминале выполните:

```bash
npm run compile
node dist/main.cli.js --generate 100 mocks/generated.tsv http://localhost:3000/db
```

Первый аргумент — положительное целое количество предложений, второй — путь к TSV, третий — URL объекта с массивом `offers`. Файл перезаписывается. TSV содержит заголовок и по одной строке на предложение. Сгенерированные TSV исключены из Git, кроме исходного `mocks/test.tsv`.

#### Импортировать предложения

```bash
node dist/main.cli.js --import mocks/generated.tsv
```

Читает TSV по строкам и выводит предложения в консоль. Для проверки больших файлов вывод можно перенаправить:

```bash
node dist/main.cli.js --generate 3500000 mocks/large.tsv http://localhost:3000/db
node dist/main.cli.js --import mocks/large.tsv > /dev/null
```
